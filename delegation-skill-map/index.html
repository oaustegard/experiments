Delegation skill map

Snapshot 2026-10-14 of /mnt/skills/user/ (115 directories), plus the agent types, tools and docs that sit beside them. Frontmatter fields, lengths and versions are read from the files; the groupings and the overlap verdicts are my judgment.

Summary

Fourteen skills touch agents or delegation. They answer six different questions, and most of the apparent overlap is two pairs of near-duplicates plus one shim:

  • Where does the work run? dispatching-subagents (Claude Code: Agent tool vs Workflow vs headless claude -p), orchestrating-chat-agents (claude.ai, no subagent tools), swarming-failing-tests (hours-long swarm), create_session (outlives the container; documented in docs/delegation.md, not a skill).
  • What does the child know? delegating-with-context (hook appends transcript chunks to the prompt).
  • Which model and effort? agent-routing.
  • What shape is the task? flowing (fixed DAG, no model between steps), tiling-tree (MECE exploration), convening-experts (panel), challenging (adversarial review), deciding-with-confidence (classification).
  • Which other vendor's agent? invoking-gemini, invoking-antigravity.
  • Legacy: orchestrating-agents (deprecated alias), orchestrating-skills (claude.ai-only in practice).

The four skills Oskar originally meant (dispatching-subagents, agent-routing, delegating-with-context, orchestrating-*) are distinct once you fix the surface and the question. They look alike because all four descriptions open with "subagent" vocabulary. Descriptions already route them well: 173 of 174 correct picks in subagent-skill-choice, against 55–85% on names alone.

Decision path

Take the first yes.

  1. Are you in claude.ai chat or the bare API, with no Agent/Workflow tool? → orchestrating-chat-agents (Claude fan-out over httpx) or invoking-gemini (cheaper, any surface).
  2. Is the procedure a fixed sequence with no model judgment between steps? → flowing. No agents involved.
  3. Is it one classify / route / yes-no / score call per item? → Muninn decide (Jev), then deciding-with-confidence, then the decider agent. Per-item subagents cost ~32.5K tokens of overhead each.
  4. Must the work outlive this container, or run a different main-loop model with hooks? → create_session, per docs/delegation.md (no skill).
  5. Hundreds of failing tests, hours of runtime, merge gate needed? → swarming-failing-tests.
  6. Fan-out in Claude Code? → dispatching-subagents picks the mechanism (Agent tool, Workflow, headless). Then write the prompt with delegating-with-context when using Agent or create_session, and choose model and effort with agent-routing.
  7. Want a particular thinking method rather than throughput? → tiling-tree (exhaustive partition), convening-experts (named perspectives), challenging (attack a finished deliverable).
  8. Want a non-Claude agent? → invoking-antigravity (agy CLI).

Axes that separate them

Surface

claude.ai chat: orchestrating-chat-agents. Claude Code / CCotw: everything else. orchestrating-skills and tiling-tree run through the chat-agents path and say to use the native runtime in Claude Code.

Decision type

Mechanism (dispatching), model/effort (agent-routing), prompt content (delegating-with-context), method (tiling-tree, convening-experts, challenging).

Scale

One question: Agent tool directly, no skill. Under 10: Agent tool. 10+: headless. Hundreds for hours with a gate: swarming-failing-tests.

Determinism

No model between steps: flowing. Model judgment between steps: Agent tool or Workflow.

Pairs people confuse

dispatching-subagents vs agent-routing

dispatching decides how to launch (mechanism, concurrency, ledger). agent-routing decides what each child runs on (model, effort, cascade). You typically need both, in that order. The one misrouted request in the earlier test, "fan out 300 tests, which model?", contains both questions.

dispatching-subagents vs delegating-with-context

One chooses the launcher; the other writes the prompt. delegating-with-context only applies to the Agent tool and create_session, because headless children have no hook and need their context written into the task file.

dispatching-subagents vs swarming-failing-tests

One-off independent tasks with no merging vs a multi-hour loop with clustering, worktrees and a merge gate. The swarm reuses the dispatcher's headless runner per worker.

orchestrating-chat-agents vs orchestrating-agents vs orchestrating-skills

Same job (httpx fan-out for surfaces without subagents), three directories. orchestrating-agents is a redirect. orchestrating-skills adds skill-typed planning and context slicing but has its own text telling Claude Code users to go native.

tiling-tree vs convening-experts vs challenging

Tiling tree spawns real parallel agents to cover a space exhaustively. Convening experts runs a persona panel toward one synthesized recommendation. Challenging attacks one finished artifact from a fresh context. Different outputs: an option map, a recommendation, a verdict with severities.

flowing vs a Workflow script

flowing enforces a fixed DAG of plain functions and cannot reason between steps. A Workflow script orchestrates agents and needs user opt-in. Both give phases, retries and resume; the difference is whether a model sits inside the steps.

deciding-with-confidence vs decider vs Jev

One capability, three implementations, in preference order: Muninn decide, then the skill's script, then the decider agent. Each says the others are slower or less accurate.

invoking-gemini vs invoking-antigravity

API calls to a model vs a full agent harness (agy) that can use tools in its own sandbox.

Where the nuance can be cut

  1. Delete orchestrating-agents. A 32-line redirect whose description starts "DEPRECATED". It still costs a catalogue slot and was the most misleading name in the earlier test (10 of 45 dispatch picks). It also exists in the plugin copy under plugins/ai-and-reasoning/. The condition for deleting: nothing imports its scripts. Check with xr first.
  2. Fold orchestrating-skills and tiling-tree behind orchestrating-chat-agents. Both carry a block telling Claude Code users to use something else, so they only apply in claude.ai, where this inventory's other skills mostly don't. Keep them, but mark the surface in the first words of the description ("claude.ai only:") so a Claude Code session never loads them.
  3. Make docs/delegation.md point at dispatching-subagents instead of restating its rule 4–5. Two places hold the Agent-vs-headless threshold; they will drift. The doc keeps the create_session rules, which no skill covers.
  4. Descriptions run 264–1010 characters with no common shape. Only flowing, dispatching-subagents, swarming-failing-tests and agent-routing list quoted trigger phrases and negative cases in the description itself. A fixed template (verb phrase, "Use for", "Not for → X") would let the pairs above separate on the first line.
  5. Surface is the cheapest discriminator and is inconsistent. Only agent-routing has the compatibility field; the rest encode surface in prose. Setting compatibility on all fourteen would make "claude.ai vs Claude Code" machine-readable.
  6. Leave alone: flowing, challenging, convening-experts, invoking-*, deciding-with-confidence. They answer questions no other skill does; they sit near the delegation cluster by vocabulary, not by function.

Not measured here: whether people (rather than a model reading skill bodies) pick correctly. The earlier experiment left that open too.
