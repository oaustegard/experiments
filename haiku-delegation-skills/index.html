Haiku delegation skills

Snapshot 2026-11-18 of the 128 entries in oaustegard/claude-skills, Oskar Austegard's skill collection for Claude. Each card says what the skill does and when you would reach for it when the worker is Claude Haiku 5.5. Versions and numbers are read from each SKILL.md; the grouping and the advice are the judgment of Muninn, the Claude-based assistant that wrote this page. Each skill lives at <name>/SKILL.md in that repo, if you want to check a claim. The 2026-10-14 delegation skill map covers all agent skills regardless of model; this page covers only delegation to Haiku and includes three skills written after that map (evolving-with-swarms, hallucinating-labels, verifying-review-findings).

Why Haiku is the default worker

Haiku 5.5 lists at $0.10 in and $0.50 out per million tokens, 20× under Sonnet 5.5 on every token class. One subagent launched through Claude Code's Agent tool costs $0.005–0.011 on a small repo against Sonnet's $0.17. agent-routing's rule is that short, checkable work goes to Haiku and the burden of proof is on routing up. Its own test battery (240 arithmetic, state-tracking and exact-constraint items, all passed) ran on Haiku 4.5; the 5.5 evidence is an independent 60-item run where Haiku scored 0.968 against Sonnet's 0.994 for about 1/16 of the cost, on tasks that each stated their rule and had one checkable answer. The skills below differ in what they help with: deciding to delegate, writing the prompt, launching the children, or doing one specific job with Haiku inside.

Which one to open

Take the first yes. Jev is a small decision model from TypeSafe that returns a probability for each option in 0.1–0.3 s; Oskar's sessions reach it through the decide tool of Muninn, his memory server.

  1. One classify, route, yes/no or score call per item? Call Jev if your session has a tool for it; otherwise deciding-with-confidence. If the label set is too big to put in a prompt, hallucinating-labels.
  2. Checking findings from a code review? verifying-review-findings.
  3. A program to improve against a numeric scorer on a small budget? evolving-with-swarms.
  4. Hundreds of failing tests and hours of runtime? swarming-to-green.
  5. Otherwise you are fanning out generic tasks. In Claude Code, dispatching-subagents picks the mechanism; in claude.ai chat, orchestrating-chat-agents.
  6. Before the launch: agent-routing confirms Haiku is the right tier and sets the escalation path; down-skilling writes the prompt when the task needs judgment; delegating-with-context keeps the Agent-tool prompt to the task alone.

Deciding and prompting

Skills that run no agents themselves. They settle whether Haiku gets the task, and what it is told.

agent-routing

2.9.1

Picks the model, effort and cascade for each subagent from measured cost per completed task, not per-token price.

Use when
You are choosing a subagent's model or effort, or deciding how to escalate after a failure. Its routing table sends extraction, classification, state tracking, bulk scans and tested code edits to Haiku, with a second Haiku attempt that is told why the first failed, then Sonnet on a second failure.
Not for
claude.ai chat. Judging another model's output, which it routes to Sonnet or above so the judge differs from the worker.

down-skilling

1.7.1

Turns Opus-level understanding of a task into a prompt Haiku can follow: rules, output schema and boundary examples.

Use when
The output needs judgment (tone, relevance, moderation) and Haiku will run it many times. For Haiku 5.5 it starts from a bare prompt and adds one rule or one boundary example per miss on a 10–20 item test set, typically ending at 0–3 examples.
Not for
Mechanically checkable output: write a verifier and retry instead. Don't instruct Haiku 5.5's thinking either, since it follows such instructions near 0% of the time.

writing-instructions

0.3.0

Sentence-level craft for instructions, with per-tier calibration: Haiku gets explicit imperatives and decision trees ("When X, do Y").

Use when
An existing Haiku prompt or skill is being ignored or misread and the fix is in the wording.
Not for
Building a Haiku prompt from scratch with a test set; that is down-skilling.

reasoning-semiformally

0.4.0

Certificate-style reasoning for patch verification, fault localization and patch equivalence. Ships reasoning-semiformally/haiku.md with full procedural templates and worked examples.

Use when
A Haiku worker has to reason about code across files: hand it haiku.md as part of its prompt.
Not for
Choosing or launching the worker.

Launching from Claude Code

dispatching-subagents

0.3.0

Chooses between the Agent tool, the Workflow tool (a JavaScript script that orchestrates many subagents) and headless claude -p children, and runs the headless fan-out from one background command with a cost cap, schema-verified outputs and resume.

Use when
Ten or more independent tasks whose inputs fit in a prompt or file and whose output a script can check: judges, graders, extractors, per-file reviews. --model haiku --concurrency 16 --max-usd 5 is the stock call; headless children are limited by RAM (about 210 MB each), while a Workflow runs only 2 at once on a 4-vCPU container.
Not for
A child that needs MCP, the parent's transcript or a worktree (use the Agent tool), or work where task N+1 depends on N's answer.

delegating-with-context

0.3.0

Lets you write only the task in an Agent or create_session prompt; a PreToolUse hook searches the parent transcript with Jev and appends the chunks the task needs.

Use when
Any Agent-tool delegation in a session that has history the child needs. Run scripts/preview.py first to see which chunks it would pass.
Not for
Headless children (no hooks run there) or claude.ai, where the hook is not wired.

Haiku as a per-item worker

Each of these does one job and runs Haiku inside it. A Haiku Agent-tool subagent costs about 32,500 tokens before it reads your prompt, so all three batch items or call the API rather than spawn one subagent per item.

deciding-with-confidence

0.4.0

Routes, triages, flags and rates text with a probability for every option, using the request and response formats of two hosted decision APIs (OpenAI's Decisions API and TypeSafe's System One), so code written for either works unchanged.

Use when
Jev is not available and you need "which queue", "is this grounded", "how severe" with a calibrated confidence. Takes a file or the session transcript as evidence.
Not for
Free-form extraction or explanations. When Jev is listed, call it: 0.1–0.3 s against ~0.7–4 s through this skill.

hallucinating-labels

0.1.0

Assigns items to a closed vocabulary too large for a prompt: a cheap model writes the label it expects, and an embedder snaps it to the nearest legal value.

Use when
Taxonomies, tag lists or code lists of thousands of labels, or an enum a provider rejects. Batch 40 items per call.
Not for
A vocabulary that fits in a prompt: on the WANDS product-search benchmark, shipping all 860 labels got the top label right 70.1% of the time against this skill's 56.4%.

verifying-review-findings

0.1.1

Drops review findings whose quoted code is not in the file, then asks a decision model whether each remaining defect is real, with P(confirmed), severity and whether the fix works.

Use when
Filtering a reviewer's false positives, or a CI gate that blocks only on confirmed high-severity findings.
Note
Jev is the primary verifier; Haiku through deciding-with-confidence is the fallback path.

Haiku swarms

Both run many Haiku workers through headless claude -p for long stretches, with a harness that checks every result.

evolving-with-swarms

0.1.1

Evolutionary program search, like the open-source OpenEvolve, on a budget: per round, eight Haiku proposers at low effort each suggest a 45-word idea and one writer at medium effort turns them into a program that a scorer ranks, all under a dollar cap.

Use when
One program, a script that scores it, and a small budget. It reached 99% of the best known score for $0.013–0.50 where a Sonnet loop needed $0.32–1.02.
Not for
When wall-clock time matters and $3+ is available: Sonnet reaches the same final scores in 7–42 minutes, while the swarm runs at about $1 an hour.

swarming-to-green

0.7.1

Hundreds to thousands of Haiku coding workers drive a failing-test backlog to green: failures clustered by signature, one worktree per fix, a serial merge gate that rejects any fix that breaks another test, retries at higher effort, resume across restarts, and the option to spread the work over several cloud sessions.

Use when
Machine-readable test output, hundreds of failures, and hours of runtime. Haiku solved clusters at $0.011–0.012 each against Sonnet's $0.075–0.087.
Not for
A handful of failing tests, or fewer than ten tasks; use the Agent tool directly.

Fan-out from claude.ai chat

Chat has no Agent tool, so these call the model APIs directly. orchestrating-chat-agents names Gemini (through Cloudflare) as the default engine in chat and its Claude path for when you want Claude output; that path and the skills built on it default to Sonnet 5.5, so pass a Haiku model id where the task fits the routing table. In Claude Code each one says to use the Agent or Workflow tool instead. orchestrating-agents is a deprecated alias of orchestrating-chat-agents.

orchestrating-chat-agents

1.0.0

Parallel Claude calls over httpx with a shared cached context, streaming, cached conversation threads and named agent pools; also delegates to Gemini through Cloudflare.

Use when
Multi-perspective analysis or task decomposition from claude.ai when you want Claude rather than Gemini output, cached multi-turn threads, or Python that calls several Claude instances at once.
Not for
Claude Code, where dispatching-subagents applies.

orchestrating-skills

0.4.1

Plans skill-typed subtasks, hands each only the slice of context it needs, runs them in parallel and synthesizes; answers trivial lookups inline without spawning.

Use when
A large text context in chat where subtasks each need only part of it.
Not for
Tool use or code execution; it is text analysis only.

tiling-tree

1.1.1

Partitions a problem into mutually exclusive, collectively exhaustive subsets recursively through parallel subagents, then scores the leaf ideas.

Use when
"What are all the ways to…": exhaustive exploration rather than throughput. Its script hard-codes Sonnet 5.5 with no option to change it, so Haiku means editing the script.

convening-experts

1.2.1

Runs a panel of named expert perspectives (domain roles, DMAIC, RAPID, Socratic and Stoic methods) over one problem.

Use when
A decision or root-cause question that benefits from distinct viewpoints, from chat.

challenging

0.13.0

Adversarial review of a finished deliverable by a fresh-context subagent (Task tool in Claude Code, API in chat), returning structured findings and a verdict.

Use when
Before shipping a post, recommendation or code where accuracy beats speed. agent-routing sends judging to Sonnet or above, so the reviewer is rarely Haiku.

Beside the skills

Three Haiku entry points in Oskar's private claude-workspace repo are not skills. Both agent types are defined in its .claude/agents/. The decider agent type is the Haiku stand-in for Jev, fed by scripts/decide.py emit and pooled by decide.py aggregate. The auditor agent type is a read-only Haiku checker for fan-out audits, with Bash gated read-only and Write limited to one declared output path. scripts/fanout.py dispatches the same {id, prompt, out} task file as the headless runner in dispatching-subagents, but over the Agent tool, so one task list runs on either engine.
