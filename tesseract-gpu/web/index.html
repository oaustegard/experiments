Read a page with Tesseract, on your own GPU

Drop a scan, a photo or a PDF. Each text line is flat-fielded and cropped tightly to its ink, and Tesseract's LSTM recognizer, ported to WebGPU, reads every line in one batch, in any of the 320 LSTM models in tessdata_fast and tessdata_best (about 160 languages and scripts, each in both sizes; the legacy-only equ and osd models are not offered). Math is read as plain text. The page is not uploaded anywhere. Models load on first use from this site, jsDelivr and Tesseract's public repository. It needs a browser with WebGPU; without one the page shows a message and does nothing else.

fast: Google's 8-bit model, about 1 to 5 MB a language. best: the float model, about 1.5 to 15 MB, slightly more accurate.

Page

Text, in reading order

    How it works: Tesseract's layout analysis (tesslayout.js, the tesseract.js-core build of Tesseract 5.1) finds the text lines and their reading order; Column bands reorders them by the column structure of the page instead (layout.js). Each line is cropped from the page and, with clean-up on, flat-fielded (the paper's uneven lighting divided out) and cropped tightly to its ink (lineprep.js). Every line is then read on the GPU by Tesseract's LSTM recognizer, the same network Tesseract 5 runs on the CPU, ported to WebGPU kernels, with Tesseract's beam search and the model's word lists for the text. The word lists are off by default for the fine-tuned English model, which reads better without them. With clean-up off, each line is cropped with 3 px of padding and read as is.

    Downloads: Tesseract's layout engine (about 2.8 MB) and the English model it uses for layout (about 4 MB) load once, from jsDelivr. The recognizer model for the language you pick loads on first use of it.

    PDFs: each page is rendered by pdf.js (Mozilla, Apache-2.0, loaded from jsDelivr on first use) at about 240 dpi and read like an image, so scanned and born-digital PDFs are both OCR'd.
