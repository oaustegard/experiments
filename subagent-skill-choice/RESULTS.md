# RESULTS: which subagent skill does a model pick?

Four skills in `oaustegard/claude-skills` compete for "run these with
subagents": `dispatching-subagents`, `agent-routing`, `orchestrating-agents`
and `delegating-with-context`, with `flowing`, `workflow-authoring`,
`invoking-gemini` and `deciding-with-confidence` nearby. Oskar asked
(2026-10-11) whether a model or a person would know which one to reach for.

## Answer

A model given the skill descriptions does; a reader scanning names does not.
Asked to pick the skill to load first for 58 requests, from the full catalogue
of 103 skill descriptions, Haiku 5.5 and Opus 5.5 chose correctly 58 of 58
times and Sonnet 5.5 57 of 58: 173 of 174, including all 24 vague requests
("Parallelize this.", "Farm this out to some agents."). With the descriptions
replaced by nothing, so that only names remained, accuracy fell to 60%
(Haiku), 55% (Sonnet) and 85% (Opus). The commonest mistake was sending a
parallel-dispatch request to `orchestrating-agents` (10 times), then sending a
`flowing` pipeline to `workflow-authoring` (9).

What would change this: requests written by people rather than by a model
reading the skill bodies, and a test of whether the model loads a skill at all
instead of being asked to choose one.

## Findings

1. **Descriptions route these skills almost perfectly.** 173/174 picks were
   correct with descriptions; the one miss sent "fan out 300 tests, which
   model?" to `dispatching-subagents` instead of `agent-routing`, and named
   `agent-routing` second. (`score-before.json`)
2. **Names alone route at 55–85%.** Opus 0.845, Haiku 0.603, Sonnet 0.552 top-1
   over the same 58 requests. (`score-names.json`)
3. **`orchestrating-agents` is the name that misleads most.** It drew 10 of 45
   dispatch picks under names only. Its content is now mostly the claude.ai
   API fan-out, which the name does not say. (`score-names.json`)
4. **Overlap in descriptions did not cost accuracy.** `delegating-with-context`
   lists "run agents in parallel" among its triggers, the same territory as
   `dispatching-subagents`, and no model confused the two with descriptions
   present. (`score-before.json`)

## Method

- **Catalogue.** Name and description of every skill in claude-skills (102)
  plus the built-in `workflow-authoring`, listed in a fixed shuffled order as
  the system prompt (`catalogue.py`, `catalogue-before.json`). The names-only
  arm keeps the names and blanks every description.
- **Requests.** 42 generated by Sonnet 5.5 from the *body* of each of 7 skills
  (6 each), told not to reuse the skill's name or phrases. Plus 8 boundary
  requests and 8 vague requests written by hand. Gold labels were reviewed by
  hand; 2 generated and 5 vague requests accept either of two skills.
- **Selection.** Each model, through headless `claude -p` with no tools and
  structured output, names the one skill it would load first and a second.
  Forced choice, one sample per request and model.
- **Cost.** $3.50 in all (`run.py`; dispatched with
  `dispatching-subagents/scripts/headless_fanout.py`).
