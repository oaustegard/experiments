# Verification: the encoding contract and `.npz` persistence

How to run this file: install remex at the commit in the document footers into a fresh virtual environment (`pip install -e .` in the remex checkout), with NumPy and SciPy and no `REMEX_*` environment variables set. Each item is a short Python script run in a new temporary directory; "Device" is the condition it needs: `py` is a plain Python process, `proc` needs a child process the item can kill, `env` needs an environment variable set for one process. Every item here is automated in [`run_pass.py`](run_pass.py), whose ID matches the row; the Steps column says what it does.

Not checkable by hand:

- Disk full during `save`, and a file replaced while `load` reads it: the expected results are read from code; reproducing them needs a size-limited filesystem and a timing harness ([Cancel and interrupt](../persistence/npz-files.md#cancel-and-interrupt)).
- Concurrent mutation of a container during `save`: the document records it as undetermined.
- Whether `save` should write atomically, and whether the seed should be recorded, are product decisions ([B-01](../bug-triage.md#b-01-a-different-seed-decodes-without-error-to-unrelated-vectors), [B-02](../bug-triage.md#b-02-an-interrupted-save-destroys-the-file-it-was-overwriting)).
