# hyde-recall — HyDE query expansion over Muninn's FTS5 memory corpus

**Status: negative, and abandoned mid-run.** This was built on a misreading of what
was asked for — the real request was `../hypothetical-classification/`, which is a
different problem. It is kept because it closes an open question `METHODS.md`
records, and because it is the third consistent negative result for query expansion
on this account's corpora.

**Question.** HyDE (arXiv 2212.10496) generates a hypothetical answer document from
a query, embeds it, and retrieves real documents near that embedding — the encoder's
dense bottleneck filters out the hallucinated specifics. Does it transfer to
Muninn's memory store, whose retrieval is Turso FTS5 (BM25 over an OR of prefix
terms), not a dense index?

**Method.** 80 questions generated by `gemini-3.5-flash-lite` from randomly sampled
memories, each instructed to avoid the source memory's distinctive vocabulary — the
vocabulary-divergence case expansion is supposed to bridge. Score: is the source
memory retrieved, and at what rank. Corpus 3,052 memories.

## Results

| policy | R (target retrieved) | cost |
|---|---|---|
| plain `recall(n=10)` | 20/80 = 0.250 | free |
| plain `recall(n=20)` | 25/80 = 0.312 | free |
| **plain `recall(n=40)`** | **42/80 = 0.525** | **free** |
| HyDE, corpus-DF-filtered terms, @10 | 21/80 = 0.263 | 3 Gemini calls, ~2 s |
| HyDE, pseudo-document as the query, @10 | 21/80 = 0.263 | same |
| HyDE, pseudo-document as the query, @20 | 31/80 = 0.388 | same |
| HyDE, **no corpus exemplars**, @10 | 14/80 = 0.175 | same |
| union of base@10 and HyDE@10 | 27/80 = 0.338 | same |

Gated escalation (run HyDE only when `term_coverage_judge` calls the baseline pool
insufficient): 0.300 at threshold 0.50, against an oracle ceiling of 0.338 for
"baseline, else HyDE".

## Findings

1. **Retrieval depth dominates every HyDE arm, for free.** `recall(n=40)` scores
   0.525 against the best HyDE configuration's 0.388 at n=20. Muninn's default recall
   depth of 10 is the actual finding here: it leaves half the reachable targets on the
   floor at zero cost. On a 3,052-document corpus, reading further is cheaper than
   generating.

2. **HyDE at matched depth is a wash.** 0.263 vs 0.250 at n=10 (21 vs 20 of 80) —
   noise. HyDE's filter is the dense encoder's lossy bottleneck; BM25 has none. A
   hallucinated term is either absent from the corpus, contributing nothing, or present
   and pulling in an off-topic match. It cannot compress.

3. **Corpus-conditioned generation is load-bearing, and its absence is worse than
   nothing.** Generating pseudo-documents without real corpus excerpts as exemplars
   scored 0.175, *below* the 0.250 baseline. The same register failure that
   `../hypothetical-classification/` measures at scale.

4. **The confidence gate `METHODS.md` records as unmeasured is now measured, and it
   does not rescue the pattern.** `nl2sh-dense` notes "a gate that expands only on low
   retrieval confidence remains unmeasured". Term-coverage gating gets 0.300 against a
   0.338 oracle ceiling and still loses 5 queries outright. About half the available
   headroom, and the headroom is smaller than just asking for more rows.

Consistent with `nl2sh-dense` (RM3 0.262→0.226, dense-PRF 0.232-0.299) and
`muninn-rm3` (RM3 tied or lost on 73 posts). Query expansion has now lost three times
on this account's corpora, in unsupervised, cross-arm and generative forms.
